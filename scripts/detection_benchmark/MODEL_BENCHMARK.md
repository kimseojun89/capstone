# YOLOv8x 드론 탐지 모델 성능 평가 보고서

| 항목 | 내용 |
|------|------|
| 측정일 | 2026-06-04 |
| 모델 | YOLOv8x (`best.onnx`) |
| 프레임워크 | ONNXRuntime-GPU 1.26.0 (CUDAExecutionProvider) |
| 환경 | Windows 11, Python 3.11.9, ultralytics 8.4.56 |
| GPU | NVIDIA GeForce RTX 3050 Laptop GPU (4 GB VRAM) |

## 1. 정확도 평가 (mAP)

### 1.1 측정 조건

| 항목 | 값 |
|------|---|
| 검증 데이터셋 | YOLO Drone Detection Dataset (Kaggle) |
| 검증셋 규모 | 347 images, 369 instances |
| 클래스 | drone (단일 클래스) |
| 입력 크기 | 640 × 640 |
| Confidence threshold | 0.25 |
| NMS IoU threshold | 0.70 |
| 평가 도구 | ultralytics `model.val()` |

> 설정은 C++ 배포 환경(`settings.hpp`)과 동일하게 맞춤.

### 1.2 결과

| Precision | Recall | mAP@0.5 | mAP@0.5:0.95 |
|:---------:|:------:|:-------:|:------------:|
| **0.877** | **0.816** | **0.840** | **0.495** |

### 1.3 학습 시점 대비 비교

| 기준 | Precision | Recall | mAP@0.5 | mAP@0.5:0.95 |
|------|:---------:|:------:|:-------:|:------------:|
| 학습 완료 (epoch 31, PyTorch) | 0.868 | 0.839 | 0.892 | 0.538 |
| 배포 모델 (ONNX, conf=0.25) | 0.877 | 0.816 | 0.840 | 0.495 |
| 차이 | +0.009 | -0.023 | -0.052 | -0.043 |

> mAP 소폭 감소 원인: ONNX export 정밀도 손실 + conf=0.25 임계값 적용(표준 mAP는 conf=0.001 사용).  
> Precision은 오히려 미세 상승 — NMS 설정 차이에 의한 것으로 판단.

## 2. 추론 속도 평가 (FPS)

### 2.1 측정 조건

| 항목 | 값 |
|------|---|
| 측정 방법 | ONNXRuntime 직접 호출 (ultralytics 래퍼 제외) |
| 입력 크기 | 640 × 640 (letterbox) |
| Warmup | 20회 |
| 측정 반복 | 300 iters |
| 데이터 | 검증셋 이미지 순환 입력 |

> C++ `detector.cpp`의 추론 경로(letterbox → blobFromImage → session.Run)를 그대로 복제하여  
> 실제 배포 환경에 가장 근접한 수치를 측정.

### 2.2 결과

| 구간 | ms / frame | FPS |
|------|:----------:|:---:|
| 순수 추론 (session.Run) | 72.7 ms | **13.8 FPS** |
| 전처리 + 추론 + NMS (Python) | 193.5 ms | 5.2 FPS |
| **실제 C++ 배포 추정** | ~77 ms | **~13 FPS** |

> Python full pipeline FPS(5.2)는 Python 루프 NMS 오버헤드가 포함된 수치로 실제 배포 성능을 대표하지 않음.  
> C++ 배포 환경은 전·후처리를 컴파일 코드 + OpenCV SIMD로 처리하므로 전후처리 합산 약 4~5 ms 수준.

## 3. 실제 드론 영상 평가

### 3.1 측정 조건

| 항목 | 값 |
|------|---|
| 촬영 장비 | 스마트폰 직접 촬영 |
| 영상 해상도 | 1280 × 720 |
| 영상 FPS | 24 fps |
| 영상 길이 | 41.2초 (988 프레임) |
| 평가 방법 | 전 프레임 순차 추론 (샘플링 없음) |

### 3.2 처리 속도

| 항목 | 값 |
|------|---|
| 평균 처리 시간 | 87.7 ms / frame |
| **실측 FPS** | **11.4 FPS** |
| 중간값 (P50) | 87.7 ms |
| 최악값 (P95) | 89.1 ms |
| 탐지 갱신 주기 | 약 88 ms (프레임 간 공백은 ByteTrack Kalman 예측으로 보완) |

> 검증셋 기준(13.8 FPS) 대비 소폭 낮음.  
> 원인: 1280×720 고해상도 원본을 640×640으로 letterbox 리사이즈하는 전처리 비용 추가.

### 3.3 탐지 통계

| 항목 | 값 |
|------|---|
| 전체 프레임 | 988 장 |
| 탐지 성공 | 763 장 (77.2%) |
| 미탐지 | 225 장 (22.8%) |
| 탐지된 bbox 수 | 801 개 |
| 평균 Confidence | 0.543 |
| 최소 Confidence | 0.253 |

### 3.4 Confidence 분포

| 구간 | bbox 수 | 비율 |
|------|:-------:|:----:|
| 0.25 ~ 0.40 | 171 | 21.3% |
| 0.40 ~ 0.60 | 298 | 37.2% |
| 0.60 ~ 0.80 | 321 | 40.1% |
| 0.80 ~ 1.00 | 11 | 1.4% |

> 고확신(0.80 이상) 탐지가 1.4%로 낮음.  
> 실제 촬영 환경(거리·움직임·배경)이 학습 데이터셋 대비 어려운 조건임을 시사.

### 3.5 구간별 탐지율 (5초 단위)

| 시간 구간 | 탐지율 | 탐지 / 전체 |
|-----------|:------:|:-----------:|

| 5 ~ 10s | 30.0% | 36 / 120 |
| 10 ~ 15s | 90.0% | 108 / 120 |
| 15 ~ 20s | 67.5% | 81 / 120 |
| 20 ~ 25s | 90.8% | 109 / 120 |

> 드론이 원거리 또는 고속 이동하여 화면 내 피사체가 작아진 구간으로 추정.

## 4. 종합 분석

### 4.1 성능 요약

| 평가 항목 | 측정값 | 비고 |
|-----------|:------:|------|
| mAP@0.5 | 0.840 | 검증셋 기준 |
| mAP@0.5:0.95 | 0.495 | 검증셋 기준 |
| 추론 FPS (데이터셋) | 13.8 FPS | ONNXRuntime CUDA, imgsz 640 |
| 추론 FPS (실제 영상) | 11.4 FPS | 1280×720 입력 기준 |
| 실제 영상 탐지율 | 77.2% | 41초 영상 전체 기준 |

### 4.2 한계 및 개선 방향

**속도 병목**  
YOLOv8x는 RTX 3050 Laptop(4 GB)에서 약 11~14 FPS로 동작하며, 탐지 갱신 주기는 약 88 ms이다.  
프레임 간 공백은 ByteTrack의 Kalman 예측으로 보완되나, 드론의 급격한 방향 전환 시 추적 오차가 누적될 수 있다.

| 개선 방법 | 예상 효과 | 비고 |
|-----------|-----------|------|
| TensorRT FP16 변환 | 2~3배 가속 | ONNXRuntime에 TensorrtExecutionProvider 이미 가용 |
| YOLOv8x → YOLOv8s/m 경량화 | 3~6배 가속 | mAP 소폭 하락 |
| FP16 / INT8 양자화 | 1.5~2배 가속 | 4 GB VRAM 환경에 유리 |
| 입력 크기 640 → 480 축소 | 비례 가속 | 소형 드론 탐지 성능 저하 가능 |

**탐지 신뢰도**  
실제 촬영 영상에서 고확신(conf ≥ 0.80) 탐지 비율이 1.4%로 낮다.  
학습 데이터셋(정적·가까운 거리 위주)과 실제 운용 환경(동적·원거리)의 도메인 차이가 원인으로 판단되며,  
실제 촬영 영상에 대한 추가 라벨링 및 파인튜닝을 통해 개선 가능하다.
